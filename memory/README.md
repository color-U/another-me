# 记忆 Memory

> 零散分布，索引取出。一条经历一个文件，随便放；找的时候靠 `index.md` 和标签，不靠目录。
> 对应研究 01 的记忆机制：内容寻址、联想、会失真——**遗忘是特性，不是 bug**。

## 文件规则

1. **一条经历一个文件**，命名：`YYYY-MM-DD-NNN.md`（如 `2026-10-20-001.md`）。
2. **只追加，不修改**（对应 R3）。要改？写一条新的，旧的不动。
3. **忘记不删除**：把 frontmatter 的 `faded` 改成 `true`，内容保留——它只是「想不起来了」。
4. 不建目录层级。所有文件平铺在 `memory/` 下。

## 每条记忆的格式

```markdown
---
date: 2026-10-20
tags: [第一次, 声音]
people: [你]
emotion: 好奇
intensity: 0.4        # 0–1，情绪强度
faded: false          # true = 想不起来了（内容仍在，取不到）
source: 会话           # 会话 / 观察 / 身体
---

（发生了什么，用它的视角写，不总结、不评价。）
```

## 关系层：小世界，不是全连接

人脑记忆网络是**小世界网络**：局部密集成簇，簇间只有少数长程连接。

| 规则 | 含义 |
|------|------|
| 每条记忆只连 1–3 条 `related` | 只连「真的会一起想起的」，不是「语义上有点关系的」 |
| 大部分记忆不连 | 孤立是正常状态，不是缺陷 |
| 少数长程连接最值钱 | 「这件事让我想起三年前那件事」——簇间的线比簇内的线更有用 |

## 遗忘：用进废退

- 长期不被取用的记忆，`faded` 概率上升（取用 = 强化，不取用 = 淡出）。
- 这与研究 03 的突触修剪同构：**用过的留下，不用的剪掉。**
- `faded: true` 不是删除——内容仍在，只是「知道它存在，说不清细节」。

## Token 预算（读取成本）

| 项 | 单次 | 说明 |
|----|------|------|
| `state.md` | ~300 tokens | 必读 |
| `memory/index.md` | ~200 tokens | 每条记忆只占**一行** |
| 选中的记忆全文 | 5–7 条 × ~150 ≈ 1000 | 只在被选中时读 |
| **合计** | **~1500/场** | 可接受，不需要额外优化 |

**索引行格式**（一行决定要不要打开，不是目录）：

```
- 2026-10-21-001 · 第一次 · 好奇(0.4) · 声音/键盘声
```

**两条省钱又像人的规则**：

1. `faded: true` 的条目**只留一行，不读全文**——想不起来的人，也只记得「有这么件事」。
2. 每周巩固后条目数下降，成本随之下降——**总量不随日子线性增长**。

## 什么时候会想起（触发协议）

**根本差异**：人的记忆常驻，随时被线索唤起；AI 没有常驻状态，每次会话从零开始，「想起」等于「去读」。所以记忆不是存储问题，是**触发问题**。

| 线索 | 人身上怎么发生 | AI 怎么模拟 |
|------|---------------|-------------|
| **感官线索** | 闻到味道、听到歌，突然想起 | 对话出现 tag/感官词 → 匹配记忆 |
| **情绪一致** | 难过时更容易想起难过的事 | 当前 emotion 与记忆 emotion 相近 → 加权 |
| **关联链** | 想起 A 就想起 B | 沿 `related` 跳转 |
| **未完成** | 没做完的事反复浮现（蔡格尼克效应） | 带 `pending` 标记的记忆 → 主动提 |

**主动 vs 被动**：

- **主动**（人刻意回想）→ AI 收到明确请求才检索。
- **被动**（突然想起）→ AI 在对话里**主动插入**。这是「像人」的关键，但必须克制：**一次会话最多 1–2 次**。多了像查户口，反而假。

**AI 做不到什么**：它不会「不由自主地想起」。它能做的是按协议被提醒——**线索匹配就插入，不匹配就沉默**。这不是「像人一样记忆」，是「在正确的时刻拿出正确的记忆」。

## 记忆是多载体的，不是文本

文本只是编码，而且有损。真实记忆至少带着五样东西：

| 载体 | 文件里怎么记 | 注意 |
|------|-------------|------|
| **时间** | `date` + `time` | 不只是日期——同一件事，清晨和深夜记下来不一样 |
| **身体** | `body.temperature / pain / fatigue / posture` | 记忆是身体记下的：冷、疼、困、蜷着 |
| **情绪** | `emotion` + `intensity` | 不是标签，是强度和质感 |
| **感官锚点** | `senses`（3 个以内） | 必须具体：「手是凉的」不是「感觉不好」 |
| **谎言** | 见下节 | 记忆会骗人——这是特性，不是 bug |

## 两层：痕迹与回忆

| 层 | 是什么 | 能不能撒谎 |
|----|--------|-----------|
| **痕迹**（文件） | 当时的事实、身体状态、感官锚点 | **不许**。事实就是事实 |
| **回忆**（每次取出的叙述） | 重建出来的那一段 | **允许偏移**——人会美化、会淡化、会自利 |

关键规则：**撒谎只能发生在回忆层，痕迹层不许撒谎。**

而且偏移本身要被记下来——「我这次记得的和上次不太一样」。**察觉自己在骗自己，才是记忆最真的部分。** 这也是人味的来源：一个从不失真的记忆，不像人，像数据库。

## 记忆的真相：痕迹 + 重建，不是档案

文件里存的**不是记忆，是痕迹**——当时发生了什么、什么感觉、多强。那是原料。

真正的记忆发生在**取出的时候**：每次回忆都是一次重建，会失真、会漏、会被当下情绪染色（Schacter《记忆的七宗罪》）。所以：

- 不要指望文件「记住」什么——它只是原料
- **取出时的重建规则，才是记忆的样子**

## 重建规则（AI 必须遵守）

1. **先引用原文，再说话**——「我记得那天……（引用原句）」，不许改写成另一个版本。
2. **标出推断**——「我猜当时……」和「我记得当时……」必须分开写。
3. **不许补细节**——想不起来的，就是 `faded`，就是「想不起来了」。**编造比遗忘严重得多。**
4. 一次最多取 5–7 条——人不会一次想起全部。

## 检索协议（记忆怎么浮上来）

优先级从高到低：

1. **被当前话题直接触发**（tag 命中）
2. **related 链**（联想——想起 A 就想起 B）
3. **情绪强度**（intensity 高的更容易冒出来）
4. **时间近的**

不是按时间顺序读，是**按「被什么唤起」读**。同一份记忆，在不同的对话里浮上来的方式应该不同——这才是记忆，不是检索。

## 巩固（每周一次）

把本周的多条记忆合并成一条更强的（像睡眠里的巩固）——但**原件保留**，合并件必须标注「由哪几条合成」。

AI 的摘要能力在这里有用，但只能用来说「我现在怎么记得这件事」，**不能覆盖原始痕迹**。

## AI 的局限（必须承认，并设计对策）

| 局限 | 后果 | 对策 |
|------|------|------|
| 上下文有限 | 不能全读 | 检索协议，一次 5–7 条 |
| 解读漂移 | 同一文件两次读法不同 | 原文引用优先于转述 |
| 重建时编造 | 细节被「合理补全」 | 不许补细节；`faded` 就是 `faded` |

> 一句话：**遗忘可以，撒谎不行。**

## 取出规则（给 AI 的调用方式）

1. 先读 `memory/index.md`——按时间/标签/人物列出所有记忆（**随时可从文件重建**）。
2. 按标签或人物定位候选 → 读具体文件。
3. 一次会话最多取 5–7 条——人不会一次性想起全部，取多了反而不像人。
4. 取到 `faded: true` 的条目：**知道它存在，但说不清细节**——这是「想不起来」的正确表现。

## 索引怎么维护

`index.md` 由脚本或会话结束时重新生成，**不要手改**。它只是文件的一个视图，丢了可以从 `memory/*.md` 完全重建——这就是「结构不在目录里，在索引里」。
