## 1. Generative Agents（论文 + 复现仓库）

**出处**：Park, O'Brien, Cai, Morris, Liang & Bernstein (2023). *Generative Agents: Interactive Simulacra of Human Behavior*. UIST '23. arXiv:2304.03442. **A 级**（论文原文页已读）。复现仓库存在：`xtu1111/generative_agents`。**B 级**（未读代码）。

**机制原文**：

- 记忆对象只有三个字段：自然语言描述、创建时间戳、**最近访问时间戳**。
- 检索函数：`score = α_recency·recency + α_importance·importance + α_relevance·relevance`；三项 min-max 归一到 [0,1]；论文实现中 **α 全部取 1**；取能放进上下文窗口的 top 若干。
- recency：距上次被检索的小时数，**指数衰减，衰减因子 0.995**。
- relevance：memory embedding 与 query embedding 的余弦相似度。
- importance：创建时让 LLM 对「poignancy」打 1–10 的整数分（论文原例：打扫房间 2 分，向心动的人开口 8 分）。
- reflection（反思）：最新事件的 importance 之和**超过 150** 时触发，生成高层记忆；论文报告实际约每天 2–3 次。

**与我们的关键差异**：importance 是写作时的 LLM 打的分——这是推断，不是被给予的事实。
我们的规范禁止 AI 推断情绪；但重要性不是事实声明，是权重。可以拆开：事实字段只写被给予的，权重字段单独存、单独标注是谁打的。

## 2. Letta / MemGPT（框架）

**出处**：`letta-ai/letta`（2026-10-21 读）。**A 级（仓库状态）**：2026-08-16 起 legacy V1 server 已归入 `archive` 分支，活跃代码迁至 `letta-ai/letta-code`。
MemGPT 论文：Packer, Wooders, Lin, Fang, Patil, Stoica & Gonzalez (2023). *MemGPT: Towards LLMs as Operating Systems*. arXiv:2310.08560（UC Berkeley）。**A 级**（arXiv 页已核）。star 数（约 23.5k，2026-07 转述）**B 级**。

**机制**：OS 式分页——core memory 常驻上下文、archival memory 外部存储按需检索，突破上下文窗口限制。
core memory 由 agent 用自己的工具编辑（如 `core_memory_append`）。细节来自二手，**B 级**。

**血统问题**：persona 由开发者预写，产品形态是「有记忆的助手服务」。不是从 t=0 长的。

## 3. mem0（框架）

**出处**：`mem0ai/mem0`（2026-10-21 读）。**A 级（仓库）**。

**机制**：四个操作——ADD / UPDATE / DELETE / NOOP——作用对象是 **LLM 抽取出的「事实」，不是用户原文**。
抽取必须调 LLM（默认 gpt-4o-mini，可换）。含程序性记忆（procedural）类型。.NET 移植 `Mem0.NET` 存在。

官方主张「SOTA、比 OpenAI memory 准确率高 26%」：**C 级（厂商自述），不作依据**。

**与我们的关键差异**：它的核心流水线就是「把用户说的话改写成事实」——这正是 memory/README 明令禁止的路径。
它靠抽取策略和更新仲裁控制错误，不靠「不许改写」。我们和它是相反的路线。

## 4. Zep / Graphiti（框架）

**出处**：`getzep/graphiti`（2026-10-21 读 README）。**A 级（README）**。
论文 *Zep: A Temporal Knowledge Graph Architecture for Agent Memory*（arXiv:2501.13956，Zep AI）经 README 引用核验，**论文原文未读**。

**机制**：

- **双时序（bi-temporal）**：每条事实带有效性窗口；新事实与旧事实矛盾时，**旧事实失效而非删除**，历史保留，可查任意时点「当时什么是真的」。
- **episode = 摄入的原始数据 = ground truth**；每个派生实体/关系可溯源回 episode（lineage）。
- 混合检索：语义 embedding + BM25 + 图遍历；README 自称亚秒级延迟；托管版自称 200ms 级（**C 级**）。
- **遗忘：无。** README 原话方向是 `invalidated — not deleted`、`full temporal history preserved`。

**与我们的关系**：溯源模型（episode→派生）和 memory/README 的「痕迹 vs 回忆」两层是同构的；
它强在「可查任意时点」，我们强在「faded 衰减」——两边正好互补。

## 7. 规则草案（供机制库引用）

- **R1（A）**：检索 score = recency + importance + relevance，min-max 归一，α=1。
  importance 是权重字段不是事实字段：赋值权归当事人或观察者，写作 AI 不得以「我觉得重要」为由填写。
- **R2（B）**：反思按累积 importance 阈值触发（论文值 150，按我们的会话密度需重新标定）。
  反思产物是推断，必须标注「推断」、与事实分列存放。
- **R3（A）**：常驻层（state 摘要 + 最近 N 条痕迹原文）与归档层（memory/ 全量）分离。
  检索只发生在归档层；常驻层由规则维护，不由模型自由发挥。
- **R4（A）**：派生物必须可溯源——index 行、related 链接、反思节点，都要能指回 memory 文件名。
- **R5（C，自建）**：faded 衰减无外部对照，保留 memory/README 现设计；上线前做变异验证。

## 8. 工程结论

1. **偷机制，不搬框架。** 四件事里三件有现成机制（R1–R4），一件没人做（R5），一整块空白（Q5）。
2. **所有已查方案共享同一血统**：persona 预写 + 用户是客户。
   直接套用任何一个，都会把我们拖回「客服机器人」。这是选型的首要排除项，排在功能匹配之前。
3. **我们的不可替代性不在「记忆系统」**，在三条约束：只写被给予的、不得推断情绪、遗忘可以、撒谎不行。
   查遍现有方案，一条都没有。
4. **下一轮精读**：Hindsight 的记忆分层（与 Q3 同构，看它的 facts/experiences 分界划在哪）；
   Generative Agents 论文 §4 的 ablation 数据（observation / planning / reflection 各贡献多少可信度——
   这直接决定我们值不值得为「反思」花 token）。
