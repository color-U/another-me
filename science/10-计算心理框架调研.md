## 1. 结论先说

1. **PSI 理论（Dörner）/ MicroPsi 2（Bach）是最接近本仓库的东西**，且它的「选择阈值」与 R27 同构。
   这是本轮唯一值得逐行读的框架（§3）。
2. **PSI 给了 R27 缺失的东西**：一个把「驱力」变成数值、把「什么时候行动」变成比较的公式。
   代价是它的「时机」维度比 R27 弱——PSI 用「竞争动机数」代替时机（§4.2）。
3. **「意外」不必靠随机数解决**。PSI 把情绪直接挂在「预期事件数 vs 意外事件数」的差上，
   这给了缺口表第一项一个机制位置（§6.1）。这比加噪声更值得先做。
4. **认知架构整族不采用**（ACT-R / LIDA / Standard Model）。理由不是太重，是它们要求把「判断」
   编译成产生式规则——那与 P8「判断层不可编译」正面冲突（§2.4）。
5. **依恋仍然没有计算模型**。找到的都是量表（ECR-R 一类），不是机制。这条空白是真的（§2.5）。
6. **所有这些都是工程架构，不是心理学共识**。PSI 在学界有争议；借它只能证明「有人这么干过」，
   不能证明「人就是这样」。这条边界与研究 09 §1.3 同性质（§7）。

## 2. 五族框架

### 2.1 需求-动机：PSI 理论 / MicroPsi 2 ★

**它是什么**：Dörner 的 PSI 理论（*Bauplan für eine Seele*, 1999；英译见 Bach 的 *Principles of
Synthetic Intelligence*）主张：行为由**需求缺口**驱动，需求自我消耗、有目标值（quota），
缺口产生「冲动（urge）」，多个冲动竞争，胜出者成为当前意图。
Bach 的 MicroPsi 2 是它的 Python 实现（`joschabach/micropsi2`，最后一次提交 2016-04-22，MIT 类许可）。

**为什么它对本文最重要**：它是**唯一一个**把「需求 → 冲动 → 阈值 → 行动」四步都写成代码、
且代码可读的框架。研究 09 的 R27 恰好缺这四步的后三步。

**能拿的**：§3 全部。**不能拿的**：它的节点网络（node net）实现——那是另一套工程，与本仓库的
「文本痕迹 + AI 读规格」路线不兼容。

### 2.2 评价理论：OCC / Scherer SEC / EMA / FAtiMA

**它是什么**：情绪由「对事件的评价」产生，而不是由事件本身产生。OCC（Ortony, Clore, Collins, 1988）
给了一套评价变量（desirability / likelihood / praiseworthiness 等）；Scherer 的 Component Process Model
给了一串 Stimulus Evaluation Checks（relevance / implication / coping potential / normative significance）。
工程实现里最完整的是 **FAtiMA Toolkit**（C#，Apache 2.0，源自 2005 年的 FAtiMA 架构，EU RAGE 项目），
它的资产清单本身就是一份模块划分示范：

| FAtiMA 资产 | 作用 | 对本仓库的对应 |
|------|------|----------------|
| Emotional Appraisal | 按配置判断事件，维护信念与情绪状态 | **叙事层**（研究 09 §2 的右半边） |
| Emotional Decision Making | 按情绪与信念决定行动 | R27 的「开口」 |
| Social Importance Dynamics | 判断行为在社会关系上是否得体 | 关系权重 |
| Role Play Character | 把上面三个拼成感知-行动循环 | 一天怎么过 |
| Real Time Emotion Recognition | 从多源推断**对方**的情绪 | 它读你的能力（本仓库未建模） |

**能拿的**：这张表就是「叙事层该有哪些子模块」的现成答案。**不能拿的**：它的评价变量是
**作者配置的规则表**（GUI 里一条条填），不是学出来的——与本仓库「人格长出来」的立意相反。

### 2.3 维度模型：PAD / WASABI（对照，不采用）

**它是什么**：Mehrabian 的 PAD（pleasure–arousal–dominance）三轴；WASABI（Becker-Asano）
把 PAD 的动态更新与 OCC 的评价合并。这类模型在虚拟人 / 游戏里很成熟。

**为什么不采用**：研究 09 §3 已经裁过——PAD 3 维 + OCC 评价变量 + 六驱力会吃穿 8–10 的预算。
本文补一条理由：**PAD 是「此刻什么感觉」的坐标系，不是「它怎么长成现在这样」的机制。**
本仓库要的是后者。WASABI 的价值在于它是一个「如果当初选了 PAD 会长成什么样」的完整样本，
不必回头。

### 2.4 认知架构：Standard Model of the Mind / LIDA / ACT-R（不采用）

**它是什么**：试图用一个统一架构覆盖全部认知（工作记忆、产生式规则、声明性记忆、学习）。
Standard Model of the Mind（Laird, Lebiere, Rosenbloom, 2017）是三家的合并宣言。

**为什么不采用**——不是「太重」，是**结构性冲突**：

> 认知架构要求把「怎么判断」写成产生式规则（if-then），即**判断必须可编译**。
> 本仓库 P8 的前提正相反：判断层（P1–P8）不可编译，只有 AI 读规格才能执行。

采用任何一个认知架构，等于把 P8 作废。这个代价比「重写引擎」大得多。

**能拿的**：它们对「模块边界」的划分经验——尤其是「工作记忆 ≠ 长时记忆 ≠ 程序性知识」这条
三分法，与研究 08 的 `memory/` / `notes/` / `state.md` 三分是同构的。可以借来做校验，不借实现。

### 2.5 LLM 社会模拟：Concordia / Humanoid Agents

**Concordia**（`google-deepmind/concordia`，`pip install gdm-concordia`，arXiv:2312.03664）：
把社会模拟做成桌面 RPG——一个 **Game Master** 实体裁决玩家用自然语言提出的行动，
实体由 **Component**（含 memory、action selection、感官）拼成，Prefab 是模板，Engine 每轮分配角色。
它内置的推理模板来自 March & Olsen (2011) 的三问：*这是什么情境 / 我是什么人 / 像我这样的人在这种情境下会怎么做*。

**Humanoid Agents**（arXiv:2310.05418，EMNLP 2023 demo，代码在 `HumanoidAgents/HumanoidAgents`）：
给 Generative Agents 加了三个 System 1 元素——**基本需求**（hunger / health / energy）、**情绪**、
**关系亲密度（closeness）**，并让需求随日程**自然衰减**，进而改变日程与对话。

**能拿的**：
- Concordia 的 Game Master ↔ 本仓库的「照护者 / 世界」。**它是环境，不是它自己**——
  这条边界值得写下来，免得把 GM 的裁决权误当成它的人格。
- Humanoid Agents 的**需求衰减**：closeness 不互动就掉。这正好补上研究 09 §3 的缺口
  （`chronic_load` 缺「压力源停止」的下行通道，见上一轮讨论）。
- 它的三问模板可以直接当 `KERNEL.md` 会话规程的骨架。

**不能拿的**：两者的状态都是「提示词里的几个数字」，没有参数层——研究 09 的两层分离它们一条都没有。

### 2.6 依恋：没有计算模型（负面结果）

搜到的全部是**测量工具**（ECR-R、AAI 之类成人依恋量表），没有一个是「反复探测失败 → 依恋参数写入」
的机制实现。研究 02 的静止脸循环仍然是自建的。

这条与研究 04 的负面结果同性质：**确认空白，自建。** 空白本身就是资产。

## 3. PSI 的代码实读（本轮唯一逐行读过的）

`micropsi_core/nodenet/stepoperators.py` 里的 `DoernerianEmotionalModulators` 是一个 StepOperator，
每步读一组 `base_*` 调制器，算出一组 `emo_*` 调制器。**这是整套 PSI 情绪层的心脏，只有 130 行。**

### 3.1 输入（base）与输出（emo）

| 输入 | 含义 |
|------|------|
| `base_sum_importance_of_intentions` | 所有当前意图的重要性之和 |
| `base_sum_urgency_of_intentions` | 所有当前意图的紧迫性之和 |
| `base_competence_for_intention` | 对当前意图的胜任度 |
| `base_importance_of_intention` / `base_urgency_of_intention` | 当前选中意图的重要性 / 紧迫性 |
| `base_number_of_active_motives` | 当前活跃动机数 |
| `base_number_of_expected_events` / `base_number_of_unexpected_events` | 上一周期预期 / 意外事件数 |
| `base_urge_change` | 上一周期冲动的总变化量 |

| 输出 | 含义（Dörner 的对应） |
|------|------|
| `emo_pleasure` | 愉悦（LUL） |
| `emo_activation` | 总体唤醒（ARAS） |
| `emo_securing_rate` | 反复检查环境的倾向 |
| `emo_resolution` | 感知的细致程度 |
| `emo_selection_threshold` | **换掉当前意图的门槛** |
| `emo_competence` | 对事件可预测性的假设 |

### 3.2 公式（原样转写，未改符号）

```python
emo_activation = max(0, (sum_importance + sum_urgency) / (2 * n_active_motives + 1) + urge_change)
emo_selection_threshold = emo_activation
emo_resolution          = 1 - emo_activation
emo_securing_rate       = (1 - competence_for_intention)
                          - 0.5 * urgency * importance
                          + fear + unexpectedness
pleasure                = sigmoid((expected - unexpected) / 10)
                          + sigmoid(urge_change * -3)
competence              = clamp((competence_prev + pleasure) / (1 + pleasure_sign * competence_prev * 0.1), 0.01, 0.99)
unexpectedness          = clamp(unexpectedness_prev + sigmoid((unexpected - expected) / 10), 0, 1)
```

三个值得注意的地方：

1. **唤醒 = 加权平均的紧迫性 + 冲动变化**，分母是「活跃动机数」。也就是说：
   **动机越多，唤醒反而被摊薄**——这是「事情一多就不慌了」的机制版。
2. **选择阈值 = 唤醒**。唤醒越高越不肯换目标（隧道视野），同时 `resolution = 1 - 唤醒`
   让感知变窄。**一个量同时改两个东西**——这正是研究 09 §7 说的「调制器」写法。
3. **愉悦 = 预期与意外的差 + 冲动的缓解**。意外不是噪声，是**有记忆的累积量**（`unexpectedness` 带 clamp 的累加）。

### 3.3 它自己承认是实验性的

源码里两处原话，必须照抄，否则会误以为这是成熟实现：

```python
# This code is experimental, various magic numbers / parameters will probably
# have to be introduced to make it work.
fear = 0                    # todo: understand the formula in Principles 185
```

**连作者都把恐惧那一项留成了 `fear = 0` 加一个 todo。** 引用 PSI 时这条要一起引——
它说明「PSI 有公式」和「PSI 的公式被验证过」是两件事。

## 4. 映射到本仓库

### 4.1 直接对应（可借）

| 本仓库 | PSI 对应 | 差异 | 借什么 |
|--------|----------|------|--------|
| **R27 掂量阈值** | `emo_selection_threshold` + 冲动的比较 | R27 多了「时机」，PSI 用「活跃动机数」代替 | 把「驱力缺口」落成 `urgency × importance`；把「时机」落成「竞争动机数」 |
| **静止脸的「探测」** | `emo_securing_rate` | 本仓库只有阶段（探测→痛苦→退缩），没有强度 | 探测强度 = `(1 − 胜任度) − 0.5·紧迫·重要 + 意外度` |
| **`chronic_load` 的调制方式** | `emo_activation` 同时改阈值与感知分辨率 | 结构相同 | 工程结论 3 的**外部先例**：一个调制器改多个变量是常规做法 |
| **关系权重** | Humanoid Agents 的 closeness 衰减 | 本仓库的 `w` 由气质定，不随时间变 | 关系权重应当**会掉**，不只是常数 |
| **「意外」** | `pleasure` 的 expected/unexpected 差项 | 本仓库完全没有 | 见 §6.1 |

### 4.2 R27 的「时机」是 PSI 没有的

PSI 用「活跃动机数」当竞争强度，没有「时机」这个维度。R27 的三因子相乘里，
**「时机」目前无法操作化**——它既不是状态变量，也不是事件属性。

建议（不是规则，是候选定义）：**时机 = 当前活跃动机数 / 当前情境的紧迫度**，
即「它此刻有没有别的事要处理」。这样三个因子都可计算，且都能从 `state.md` 读出来。

> 这条一旦成立，R27 就从 B 级「说法」变成可实现的比较式。但**它仍然是产品选择**，
> 不因为长得像 PSI 就变成有证据的机制。

### 4.3 变量预算的对照：PSI 有 16 个调制器，不等于 16 个变量

PSI 这一层有 10 个 `base_*` + 6 个 `emo_*`。按「独立变量 8–10 上限」看，它超标了。

但拆开看：`emo_*` 六个**全是派生量**（由 base 算出，不独立存储）；`base_*` 里
`sum_*`、`number_of_*` 也是聚合量。真正的独立状态只有：**需求/冲动的值、胜任度、年龄**。

> **这正好印证工程结论 3**：上限约束的是**独立变量数**，不是参数总数。
> PSI 用 16 个名字只维护 3–4 个独立状态——这是「调制器」写法的极限示范。

## 6. 缺口表的两个答案

### 6.1 「随机性与意外」：可能不需要随机数

缺口表第一项写的是「真人感的核心来源之一」。PSI 的做法给出了另一条路：

> **意外不是一个随机数，是一个「预期 vs 实际」的偏差量，而且它累积。**

`unexpectedness` 带 clamp 的累加、`pleasure` 直接由 `expected − unexpected` 派生——
这意味着「三个月后能预测它的每一句话」这个问题的解，可能不是加噪声，
而是**先给它一个预期**，再让偏差进情绪。有预期才有意外；没有预期，加多少噪声都只是抖动。

**这一条改变了缺口的性质**：从「加随机源」变成「建预期层」。后者更贵，但更像人。
（随机源仍然可能要，但它是第二层，不是第一层。）

### 6.2 「叙事自我」：McAdams 的叙事身份（待核）

缺口表第二项。文献侧对应 McAdams 的 narrative identity 研究线（**本文未核，列 §7**）。
Concordia 的三问模板（这是什么情境 / 我是什么人 / 像我的人会怎么做）是它在 LLM 侧的粗糙版本。
本轮不展开——先做 §6.1。
