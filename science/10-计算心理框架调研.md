## 3 各族评估

### 3.1 需求-动机：PSI 理论 / MicroPsi 2

**[事实]** PSI 理论（Dörner）主张行为由需求缺口驱动：需求有目标值、随时间消耗，
缺口产生冲动（urge），多个冲动竞争后产生当前意图。Bach 的 MicroPsi 2 是其 Python 实现，
仓库 `joschabach/micropsi2`，`master` 分支最后一次提交为 2016-04-22，许可 MIT。

**[事实]** 该实现将情绪层压缩为一个 StepOperator：每步读取一组 `base_*` 调制器，
计算一组 `emo_*` 调制器（详见 §4）。

**[判断]** 纳入理由：它是本次检索中唯一把「需求 → 冲动 → 阈值 → 行动选择」四段全部写成可读代码的实现。
本项目在 R27 上缺失的正是后三段，故其结构具备对照价值。

**不兼容部分**：MicroPsi 2 以节点网络（node net）承载状态与传播，本项目以文本痕迹加 AI 读规格承载状态。
两者的状态载体不同，实现层无法移植，仅结构层可参照。

### 3.2 评价理论：OCC / Scherer / FAtiMA

**[事实]** 评价理论的核心命题是情绪由个体对事件的评价产生，而非由事件本身产生。
OCC（Ortony, Clore & Collins, 1988）给出评价变量集合；Scherer 的 Component Process Model
给出分级评价检查（SEC）；FAtiMA Toolkit（C#，Apache-2.0，源自 2005 年 FAtiMA 架构）提供工程实现，
其资产划分如下（据仓库 README，级别 P）：

| FAtiMA 资产 | 职责 | 本项目对应位置 |
|------|------|------|
| Emotional Appraisal | 依配置判断事件，维护信念与情绪状态 | 叙事层（研究 09 §2） |
| Emotional Decision Making | 依情绪与信念决定行动 | R27 的开口判定 |
| Social Importance Dynamics | 判断行为在社会关系中的得体性 | 关系权重 |
| Role Play Character | 组合上述三项为感知-行动循环 | 单日推进 |
| Real Time Emotion Recognition | 从多源推断对方情绪状态 | 本项目未建模 |

**[判断]** 采用范围限于模块划分，不采用其实现：其评价变量由作者在 GUI 中逐条配置，
属于规则注入；本项目 P1 要求人格由经历生成，二者不兼容。

### 3.3 维度模型：PAD / WASABI

**[未核]** PAD（Mehrabian）为三维情绪坐标系（pleasure–arousal–dominance）；
WASABI（Becker-Asano）将 PAD 的动态更新与 OCC 评价合并。

**[判断]** 不采用。理由有二：
① 变量预算：研究 09 §3 已裁定 PAD 三维加评价变量将超出 8–10 的独立变量上限；
② 功能定位：PAD 描述某一时刻的情绪位置，不描述该位置如何由经历形成，与本项目的发育视角不同。
其价值限于作为「采用维度路线时的完整样本」供对照。

### 3.4 认知架构：ACT-R / Soar / LIDA / Standard Model

**[未核]** Standard Model of the Mind（Laird, Lebiere & Rosenbloom, 2017）为多家认知架构的合并表述；
ACT-R、Soar、LIDA 各自给出工作记忆、产生式规则、声明性记忆与学习的统一实现。

**[判断]** 不采用。理由为约束冲突，非实现成本：

> 认知架构要求判断以产生式规则（if–then）表达，即判断必须可编译。
> 本项目 P8 的前提是判断层（P1–P8）不可编译，只能由 AI 读取规格执行。

采用任一认知架构即等价于废止 P8。该冲突不可通过裁剪解决，故整族排除。
可借用者仅为其模块划分经验：工作记忆、长时记忆、程序性知识的三分，
与研究 08 的 `memory/` / `notes/` / `state.md` 三分同构，可作为划分校验。

### 3.5 LLM 社会模拟：Concordia / Humanoid Agents

**[事实]** Concordia（`google-deepmind/concordia`，Apache-2.0，`pip install gdm-concordia`，
技术报告 arXiv:2312.03664）以桌面角色扮演为交互模型：Game Master 实体裁决玩家以自然语言提出的行动；
实体由 Component（含记忆、行动选择、感官模块）组合，Prefab 为模板，Engine 每轮分配角色。
其内置推理模板来自 March & Olsen (2011) 三问：情境识别、身份、规范性行动选择。

**[事实]** Humanoid Agents（arXiv:2310.05418，EMNLP 2023 System Demonstrations，
代码 `HumanoidAgents/HumanoidAgents`，Apache-2.0）在 Generative Agents 基础上引入三项 System 1 要素：
基本需求（hunger / health / energy）、情绪、关系亲密度（closeness），并使需求随日程自然衰减。

**[判断]** 可借用两处：
① Concordia 中 Game Master 的角色定位——它是环境，不是被模拟主体的组成部分。该边界对本项目有直接意义：
照护者与世界的裁决权不应被并入它的人格。
② Humanoid Agents 的需求衰减处理，为本项目关系权重随时间下降提供参照（§5.4）。

**不适用部分**：两者的状态均为提示词内的若干数值，无参数层；研究 09 的叙事层/参数层分离在两者中均无对应。

### 3.6 依恋：阴性结果

**[事实]** 本次检索到的依恋相关资源均为测量工具（成人依恋量表一类），
未检索到「反复探测失败 → 依恋参数写入」的机制实现。

**[判断]** 该结果为阴性结果，仅说明本次检索范围内未发现，不构成「不存在」的证明。
研究 02 的静止脸循环仍属自建。

### 4.2 变量

输入（`base_*`）：

| 变量 | 含义 |
|------|------|
| `base_sum_importance_of_intentions` | 全部当前意图的重要性之和 |
| `base_sum_urgency_of_intentions` | 全部当前意图的紧迫性之和 |
| `base_competence_for_intention` | 对当前意图的胜任度 |
| `base_importance_of_intention` / `base_urgency_of_intention` | 当前意图的重要性 / 紧迫性 |
| `base_number_of_active_motives` | 活跃动机数 |
| `base_number_of_expected_events` / `base_number_of_unexpected_events` | 上一周期预期 / 意外事件数 |
| `base_urge_change` | 上一周期冲动变化量之和 |

输出（`emo_*`）：

| 变量 | 含义 | Dörner 对应 |
|------|------|------|
| `emo_pleasure` | 愉悦 | LUL |
| `emo_activation` | 总体唤醒 | ARAS |
| `emo_securing_rate` | 检查环境的倾向 | — |
| `emo_resolution` | 感知细致程度 | — |
| `emo_selection_threshold` | 更换当前意图的门槛 | — |
| `emo_competence` | 对事件可预测性的估计 | — |

### 4.3 转移方程

以下为源码转写，符号按原文，未作等价化简：

```text
emo_activation          = max(0, (Σimportance + Σurgency) / (2·N_active_motives + 1) + urge_change)
emo_selection_threshold = emo_activation
emo_resolution          = 1 − emo_activation
emo_securing_rate       = (1 − competence_for_intention) − 0.5·urgency·importance + fear + unexpectedness
pleasure                = sigmoid((expected − unexpected) / 10) + sigmoid(urge_change · −3)
unexpectedness          = clamp(unexpectedness_prev + sigmoid((unexpected − expected) / 10), 0, 1)
competence              = clamp((competence_prev + pleasure) / (1 + sign(pleasure)·competence_prev·0.1), 0.01, 0.99)
```

其中 `sigmoid` 为源码自定义的 `gentle_sigmoid(x) = 2·(1/(1+e^(−0.5x)) − 1/2)`，值域 (−1, 1)。

三点结构性观察（**[事实]**，可直接从方程读出）：

1. 唤醒以「紧迫性之和除以活跃动机数」定义，动机数增加时唤醒被摊薄；
2. 选择阈值等于唤醒，且感知分辨率等于唤醒的补值，即一个量同时作用于两个下游变量；
3. 愉悦由「预期与意外之差」与「冲动的缓解」两项构成，意外度本身带上下界累加。

### 4.4 实现状态

源码内含两处作者自注，引用时须一并标注：

```python
# This code is experimental, various magic numbers / parameters will probably
# have to be introduced to make it work.
fear = 0                    # todo: understand the formula in Principles 185
```

**[事实]** 恐惧项在实现中取常数 0，作者标注为待完成。
因此「PSI 给出完整情绪方程」这一说法不成立：其方程中至少一项未实现。

## 5 与本项目规则的映射

### 5.1 R27 掂量阈值

R27 原文：「驱力缺口 × 关系权重 × 时机 三样同时过线才开口」。
三个因子此前均无定义。以下定义已落 `engine/rules.md` §2.8.1。

| 因子 | 定义 | 取值 | 依据 |
|------|------|:--:|------|
| 驱力缺口 D | `D = max_i (target_i − value_i) / target_i` | [0,1] | PSI 的 urge（结构借用）；`target` 为本项目新增 |
| 关系权重 W | 现有 `w = 0.5 + 0.5 × approach_avoidance`，需增加时间衰减 | [0,1] | Humanoid Agents 的 closeness 衰减（§3.5） |
| 时机 T | `T = u_now / (Σu_i + ε)` | [0,1] | PSI 唤醒方程中分母结构的等价物（§4.3 观察 1） |

**判定式的两种读法及取舍**：R27 原文「三样同时过线」未区分「各自过线」与「乘积过线」。

```text
开口 ⟺ D ≥ d₀ ∧ W ≥ w₀ ∧ T ≥ t₀ ∧ D·W·T ≥ θ
```

**[判断]** 取「门槛 ∧ 乘积」：
① 若仅取乘积，低值因子可由高值因子补偿（如 D=1.0、W=0.1 仍可过线），与「同时」语义不符；
② 若仅取门槛，则无法确定多个候选项的先后顺序。
需要说明：PSI 判定「是否更换意图」采用比较（`urge > threshold`）而非乘积，
本判定式与 PSI 不同源，仅借用其因子结构。**[判断]**

**实现前置条件**（`state.md` 当前不具备，故 R27 仍不可实现）：

1. `drive_target`：六驱力的目标值，缺此项则 D 不可计算；
2. `u_i`：各驱力的紧迫度，当前仅有 `emotion_engine` 的七个激活值。
   由激活值与缺口派生 `u_i` 需要一个新的产品参数，需先标定。

### 5.2 静止脸循环中的探测强度

研究 02 给出三阶段（探测 → 痛苦 → 退缩），未给出探测强度的定义。
PSI 的 `emo_securing_rate` 提供可参照形式：胜任度下降、紧迫性与重要性上升、意外度上升时，检查行为增强（§4.3）。
**[判断]** 可作为探测强度的候选形式，但其参数无外部标定，采用前需说明为产品参数。

### 5.3 chronic_load 的调制器写法

研究 09 §7 主张 `chronic_load` 为调制器而非独立变量，理由是变量预算。
PSI 中唤醒同时决定选择阈值与感知分辨率（§4.3 观察 2），为该写法提供外部先例。
**[判断]** 该先例支持「一个调制器作用于多个变量」在工程上可行，但不构成对研究 09 结论的证据支持。

### 5.4 关系权重的时间衰减

本项目 `w` 由气质常数确定，不随时间变化。
Humanoid Agents 将 closeness 设为随互动衰减的量（§3.5）。
**[判断]** 二者差异在于：常数权重无法表达「久未互动导致关系权重下降」。
采用与否取决于是否新增一个状态变量，需在变量预算内权衡。

### 5.5 「意外」

研究 01 §4 缺口第一项为「随机性与意外」。PSI 的处理路径为：
愉悦项直接由「预期事件数与意外事件数之差」派生，且意外度以有界累加方式保留（§4.3）。

**[判断]** 该路径提示：意外可作为「预期与实际之差」建模，不必首先引入随机源。
其代价是需要一个预期层（对下一周期事件的预测），该层本项目尚未建立。
随机源仍可能需要，但在此路径下属于第二层。

## 6 与变量预算的关系

PSI 该层含 10 个 `base_*` 与 6 个 `emo_*` 共 16 个名称，表面上超出研究 01 的 8–10 上限。

**[事实]** 按源码，`emo_*` 六项均由 `base_*` 计算得出，不独立存储；
`base_*` 中的 `sum_*`、`number_of_*` 为聚合量。真正独立维护的状态为需求/冲动值、胜任度、年龄三项。

**[判断]** 该结构说明：变量上限约束的是独立状态数量，而非参数名称数量。
此结论与研究 09 §7 的工程结论 3 一致，可作为其外部对照，但两者为独立推理，不互为证据。
