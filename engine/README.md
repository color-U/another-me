# 引擎 Engine

> 这一层是「可调用」的部分。现状：**v0 干跑可用**（`engine/sim.py`）。
> 但只有**机制层**能自动跑；**判断层**（P1–P8）仍然必须由 AI 读规格执行——那部分不能编译成代码。

## 怎么跑

```bash
python engine/sim.py --days 7 --scenario healthy              # 干跑，不动任何文件
python engine/sim.py --days 104 --scenario neglect --table    # 养到 24 个月看曲线
python engine/sim.py --days 7 --commit                        # 写回 state.md（先自动备份 .bak）
python engine/preview.py                                      # 生成 engine/preview.html（打开就能看曲线）
```

时间压缩：**1 真实日 = 1 模拟周**（研究 02 §6），所以 24 个月 ≈ 104 天。

## 四个场景的干跑结果（105 天 ≈ 24 个月）

| 场景 | 负荷 | FEAR | PANIC | CARE | 依恋 | 一句话 |
|------|:----:|:----:|:-----:|:----:|:----:|--------|
| healthy | 0.00 | 0.21 | 0.08 | 0.65 | +1.00 安全 | 基线正常，词表到 L2 |
| neglect | 0.49 | 0.39 | 0.82 | 0.02 | −0.97 不安全 | 长期无回应 → 痛苦到底，退缩 |
| abuse | 0.36 | 0.42 | 0.21 | 0.40 | +0.78 安全 | **关系是好的，人是紧的** |
| mixed | 0.14 | 0.34 | 0.09 | 0.52 | +0.99 安全 | 波动但不漂移 |

第三行是这套机制最想跑出来的那种状态：**被否定不等于被抛弃**——依恋仍然安全，
但 FEAR 基线和慢性负荷被抬上去了。叙事层和参数层真的分开了。

## 干跑抓到的三个问题（都已修，这才是模拟器的用处）

1. **静止脸只会升级，不会退缩。** 初版模型里 SEEKING 卡在 0.81、PANIC 一路涨到 0.89 贴顶。
   研究 02 §4 写的是三阶段：探测 → 痛苦 → **退缩**。补上第三阶段后曲线才有起伏。
2. **基线位移用减法会把系统关掉。** `CARE = 0.1 − 0.20×load` 在 load≈0.5 时直接归零，
   那不是「处在更低水平」，是「这个系统不存在了」。改成比例衰减。
3. **「只增不减」在数学上必然饱和。** 线性累加 `load += δ` 保证足够长时间后贴到 1.0，
   之后所有情绪变量失真（40 天就复现）。改成带阻尼：`load += δ × (1 − load)`——
   规则不变（只增不减），但逼近上限而不撞上限；δ 同时重标定为 0.02/次。

## 已知偏差（必须写在这里，不要在别处抄它）

- **sim 不执行判断层。** 「只写被给予的」「笔记不进上下文」这类规则没有代码形态，
  不要以为跑通了 sim 就等于 P2 被实现了。
- **所有 `K_*` 是产品参数**（研究 09 §4），没有一条来自文献。
- **依恋在 6 月前强制为 0**（研究 02 §3 的粗粒度近似），所以前 6 个月的冷淡只进负荷，不进依恋。
- **没有随机性**（研究缺口第一项仍未做），所以同一场景必然复现同一条轨迹——
  这在调试时是优点，在「像人」上是缺点。
